QEMU 与稳定版本流程
===================

QEMU 稳定版本
-------------

QEMU 稳定版本基于最近发布的版本，增加一位版本号，例如 2.10.1。
偶尔需要在其上追加单个紧急修复时，也会发布四段版本号。

通常只为最新主版本提供稳定版本。
例如发布 QEMU 2.11.0 后，持续提供 2.11.x 或 2.11.x.y，
直到 QEMU 2.12.0 发布，此时转而提供 2.12.x 或 2.12.x.y。

哪些修改应进入稳定版本？
------------------------

通常以下补丁适合稳定版本：

* 修复严重问题，例如 CVE。

* 修复回归问题。

如果认为补丁对当前版本用户，或选取修复的发行版很重要，
通常就是稳定版本的合适候选。


如何让补丁进入 QEMU 稳定版本
----------------------------

有多种方式：

* 首选方式：发送补丁时确保抄送稳定版本维护者，在补丁说明中加入

  .. code::

     Cc: qemu-stable@nongnu.org

  使用 git send-email 时，默认会向 ``qemu-stable@nongnu.org``
  发送副本，维护者通过该地址跟踪稳定版本候选补丁。

* 如果认为之前提交的补丁适合稳定版本，也可以回复该补丁，
  在邮件客户端直接抄送 ``qemu-stable@nongnu.org``。

* 维护者之后判断补丁适合稳定版本，或收到你的提醒时，
  会添加相同的行，使其拉取请求抄送稳定版本维护者。

* 如果认为已合并补丁适合稳定版本，发送邮件到 ``qemu-stable@nongnu.org``，
  最好回复最近一次补丁提交，并抄送 ``qemu-devel@nongnu.org``
  和相关人员，例如原作者或对应维护者。

稳定版本发布流程
----------------

维护者准备新稳定版本时，会建立包含候选版本的 Git 分支，
并向 ``qemu-devel@nongnu.org`` 发送补丁供审查。
如果包含你的补丁，请确认其正确性，尤其留意跨分支回移时维护者所作调整。
也可以提名其他合适补丁。审查完成后发布新稳定版本，期间可能产生更多候选版本。
