维护者的职责
============

维护者是贡献者生态的关键成员，背景多样：
既有利用业余时间工作的无偿爱好者，也有以参与项目为本职工作的雇员。
维护工作包括：

  - 审查补丁并提出修改建议；
  - 收集补丁、准备拉取请求；
  - 关注所负责领域的长期健康；
  - 参与其他项目活动。

维护者也是普通人，同样面临工作过载和倦怠。
与其他人一样，他们应遵守 :ref:`code_of_conduct`，
并成为优秀社区协作者的榜样。

MAINTAINERS 文件
----------------

`MAINTAINERS <https://gitlab.com/qemu-project/qemu/-/blob/master/MAINTAINERS>`__
保存正式维护者名单。文件可由机器读取，配置正确的 Git
（见 :ref:`cc_the_relevant_maintainer`）可在补丁修改对应领域时自动抄送他们。

文件还描述代码领域的维护状态，体现维护活跃程度。

.. list-table:: MAINTAINERS 中的支持状态含义
   :widths: 25 75
   :header-rows: 1

   * - 状态
     - 含义
   * - Supported
     - 有人受雇负责此部分。
   * - Maintained
     - 确实有人维护。
   * - Odd Fixes
     - 有维护者，但时间有限，通常只能偶尔提交补丁。
   * - Orphan
     - 当前没有维护者。
   * - Obsolete
     - 已过时，应使用其他实现。

有人受雇支持某个组件，不表示其工作就是为你提供支持。
这是开源项目，代码没有保证，项目也不保证处理缺陷或功能请求。



成为审查者
----------

多数维护者先从子系统审查者做起。欢迎任何人在邮件列表审查代码，
但在 MAINTAINERS 中加入类似以下内容后::

  R: Random Hacker <rhacker@example.com>

你就成为“指定审查者”，预期主动、定期提供反馈。
相关子系统的补丁也会自动抄送给你。

成为维护者
----------

维护者是主动承担，或受邀照看某个代码领域的志愿者。
通常他们已通过贡献和代码审查向社区证明，自己充分理解该子系统，
也值得信任，能够积极贡献并与其他人良好合作。

流程很简单：向邮件列表发送更新 MAINTAINERS 的补丁。
添加新子系统时，它有时属于较大补丁序列的一部分。
也可以由准备退出的维护者与其他贡献者讨论后，提名接任者。

补丁经审查合并后，剩下的步骤是确保 GPG 密钥已获得签名。

.. _maintainer_keys:

维护者 GPG 密钥
~~~~~~~~~~~~~~~

GPG 用于签名拉取请求，证明它确实来自维护者。
如果密钥尚未获得 QEMU 社区成员签名，应安排参加
`密钥签名聚会 <https://wiki.qemu.org/KeySigningParty>`__，例如 KVM Forum，
或另行安排请参会者为密钥签名。
密钥签名要求与另一位社区成员 **当面见面** [#2020]_，请作好安排。

.. [#2020] 近期疫情期间，这方面不得不适当灵活处理。
       不过维护者仍必须为拉取请求签名。
